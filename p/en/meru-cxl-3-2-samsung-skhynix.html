CXL bolts on memory like a warehouse. So why did Samsung push production to 2027?

Open in the Stacks app → Read the original ↗

Why a server runs out of memory slots

Open a computer and you see a few long slots where memory sticks go. A server is the same. The number of DRAM slots a CPU can address is fixed, because the number of dedicated lanes crossing the motherboard is fixed. If you want more memory and there is no slot left, that is the end of it. CXL routes around the limit by hanging boxes of memory off PCIe, the general purpose lane that is already there. Using the ordinary road instead of a dedicated one means capacity stops depending on slot count.

So why is nobody using it

You pay for the capacity in latency. Reading DRAM sitting next to the CPU takes 80 to 140 nanoseconds. A trip out to CXL attached memory takes 170 to 250. Close to twice as slow. What matters is that not all data is equally urgent. Keep the data you touch constantly in the fast seat next to the CPU, put the data you open once a month in the cheap warehouse, and the system slows down far less than the raw numbers suggest. Software has been doing that sorting until now. CXL 3.2, published in December 2024, moved the job into the chip. It adds a hardware unit that counts which pages are being used often, so software no longer has to sample for it.

The spec is out. Where is the product?

The spec has been sitting there for nearly two years with no product behind it. What the memory makers are waiting on is not their own fabs, it is CPUs. Modules only sell once a server CPU that speaks CXL 3.x ships.

Checked 2026-07-27 · CXL Consortium (2024-12-03) · TheElec (2026-07-07) · SK hynix Newsroom (2025-04-22)

Samsung pushed CMM-D 3.1 samples to Q4 2026 and volume production to Q1 2027. The original plan was samples in Q4 2025. The reason sits with Intel and AMD, not Samsung: Diamond Rapids slipped to Q2 or Q3 2027, and EPYC Venice moved with it. SK hynix said it finished customer validation of a 96GB module in April 2025, but named no customer and disclosed no shipment volume. Validation complete and shipping in volume are not the same sentence.

Has CXL been pushed aside, then?

The common reading

AI wants fast memory. Slow CXL lost its seat to HBM and there is nothing left for it.

Why Meta actually deploys it

Not performance, cost. It is a way to bolt memory Meta was about to scrap onto new servers.

Meta built its own chip, Vistara, to attach old DDR4 memory to new servers that only speak DDR5. One machine ends up with 768GB of fast DDR5 plus 256GB of CXL attached DDR4, about a terabyte in total. With DRAM prices climbing, Meta chose reuse over purchase.

The two technologies are not fighting over the same seat. HBM handles bandwidth next to the GPU. CXL handles capacity and cost next to the CPU. Which means what is holding CXL back right now is not HBM. It is the CPU calendar.

XCENA CEO on CXL: HBM is bandwidth, CXL is capacity and sharing (Blocks & Files, 2026-03-25)
출처: blocksandfiles.com

For a memory company, CXL is another way to sell DRAM. The date that road opens is simply not in their hands.

In three lines
  • A CPU has a fixed number of memory slots. CXL gets around that limit by hanging extra memory off the side, like a warehouse.
  • Yet Samsung has pushed volume production of its CXL 3.1 module to Q1 2027. Server CPUs slipped, and the money went to HBM.
  • Meta, meanwhile, already runs CXL in production. Not for speed, but to reuse memory it was about to throw away.

Why it matters · CXL turns memory from a fixed slot count into something you can extend. But the date that door opens is held by Intel and AMD, who make the server CPUs, not by Samsung or SK hynix.

Worth asking · CXL modules only sell once server CPUs that speak CXL 3.x arrive. That puts a memory company's new growth line on someone else's calendar. Is this a delay worth waiting out, or a window closing?
